## 建议5–8分钟演示顺序

1. 聊天：输入一句简短问候，只发送一次。说明回复经FastAPI/DeepSeek并写入MySQL；刷新再打开同一会话。失败时查看错误，不连续重发未知结果。
2. 记忆：从“我的回忆”展示已有Synthetic膝盖恢复记录、原文来源、确认/纠错/禁用/删除入口。重新登录、新建会话后如需现场问当前状态，只做一次简短提问。历史真实证据见T07/T08/T09记录。
3. 出行：优先打开已持久化的出行草案；也可输入“明天上午十点去合成书屋，记得提醒我”。系统应追问到达/出发、出发地、目的地和交通方式，不能口头保证已安排。
4. 核对卡片：明确位置用途、选地点候选、查询Mock路线天气、确认信息、生成提醒预览、最后“确认并安排提醒”。确认信息本身不会安排。演示示例35分钟车程并非实时查询。
5. 提醒页：查看已保存任务、出门/提醒时刻、通知状态；修改时间，或“修改地点和交通方式”重新核对。新卡确认前保留旧提醒，确认后旧待发job失效。可取消/已出发/完成。
6. 多用户：退出demo_a，登录demo_b；不得看到A的聊天、记忆、任务。仅使用Synthetic，不录入真实家庭地址或医疗资料。
7. 规模报告：打开docs/testing/memory-eval-v1/t11a-v1-verified.html，说明310固定题、100/1000/10000/20000条实际SQL评估。报告的答案/冲突指标使用Mock，不能宣称DeepSeek开放式准确率100%。

现场发送才会消耗真实模型额度；共享日预算默认10次请求/20000保守预留tokens。不要运行smoke脚本重复付费。历史累计7次、3218输入/376输出tokens、保守估算USD0.00141660是准备演示之前的台账，非账单；现场用量另记。

## 下次启动

项目根目录分别开三个PowerShell终端：

```powershell
.\scripts\start-dev.ps1 -Target api
.\scripts\start-dev.ps1 -Target h5
.\scripts\start-dev.ps1 -Target worker
```

本机Docker重启后先运行：

```powershell
.\.venv\Scripts\python.exe scripts/init-dev-db.py
```

不要重复启动占用相同端口的进程，不终止其他项目服务。Ctrl+C只停止自己的终端进程。停止网页不删除数据；Worker停止期间不尝试发送，到重启扫描时按15分钟有效窗口和租约策略处理，过时项可见但不盲目补发。
