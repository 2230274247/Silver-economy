# CHAT-03 日程追问与新草案占位编号修复

时间：2026-10-27T15:45:21+08:00，Asia/Hong_Kong。用户期望“明天下午有会议”后自然追问具体几点，再收集提醒偏好，参考Muse的多轮对话。

## 根因

现场模型已经产生询问具体时刻的自然reply，但把新任务编号写成draft_1。当前会话没有已存在草案，后端按非法已有引用拒绝整条结果，错误TASK_UNSUPPORTED_REFERENCE。另有date_text把“明天”和“下午”合在一起，日历解析只接受日期片段，造成已知日期被误报缺失。

## 最小修复

- 当前没有可引用草案、且用户明确表达新任务时，仅将new/draft_数字/task_数字这些本地占位标签按新草案处理，实际ID始终由数据库生成。未知真实UUID或有现存草案时仍执行原有引用/归属/版本检查。
- 从已在原文中出现的时间表达里拆出日期、时段、时刻；“明天下午”拆成明天/下午，不补造具体几点。已有时段和相对日期参考时间在下一轮保留。
- 新增task-intent/v3，保留v2原件；明确新草案编号留空，优先只问缺失的具体时间，后续再问是否提醒/提前多久，不一次盘问会议地点/时长等可选信息。chat-task/v3流水线登记匹配实际Prompt。
- 原有模型自然reply保留；草案、缺项和确认/调度由后端维护。快选按钮可作为用户回复的快捷输入，但本次未新增Muse式按钮界面，不虚称已实现。
