## 后续日志规则

1. 写明任务 ID、香港时间、功能结果、修复原因、相关文件，不用含糊的 update。
2. 给出实际命令、通过/失败及影响，保留失败与修复关联；没有测试不得写已验证。
3. 区分文档/设计交付、Mock 测试通过、真实服务接通、真机验收，不混写。
4. 记录 SHA、分支、push/SHA 核验、CI run URL/结果、未完成项和下一步。
