# ADR-002：主动生活助理与首版界面

- 日期：2026-10-26
- 状态：用户已明确调整并确认

## 产品定位与新增验收

记忆是基础，核心结果是帮助用户处理生活安排。用户举例：明天赴约，提前提醒，
计算车程、建议出门时间、根据天气提示是否带伞。
用户已确认首版先在电脑验证：网页关闭后，浏览器和本地后台服务保持运行时能收到通知；
路线/车程/天气接入真实查询服务，所需服务授权由用户在本机安全配置。

此决策覆盖原任务书 V0.1 只做站内手动提醒的范围裁剪，不改变原件。
仍按 T00–T14 顺序推进，不将新增能力提前伪造在 T02。

- T03 数据模型为事件/提醒保留准确时间、时区与用户归属；新增表通过后续 Alembic 迁移。
- T06/T07 对话理解时区、相对日期、待办候选；缺少地点/时间/交通方式时追问，用户确认后创建。
- T11 扩展为出行安排、真实路线/天气查询、带来源和查询时间的出门建议、可配置提前量、持久化调度与浏览器 Web Push。
- T12 提供通知授权/订阅状态、权限拒绝说明、隐私与数据最小化。
- T13 验收关闭网页后送达、重复执行/重启去重、权限拒绝、离线失败、用户隔离、查询超时和数据过期；不得将调度成功或推送服务接受等同用户已经看到。
- T14 如实说明需浏览器/本地后台持续运行；不承诺关机、断网或手机离开网页后的提醒。

真实查询前，需用户确认出发地/目的地/交通方式；不猜测住所、不自动获取精确定位。
地图等密钥只在服务端未跟踪环境配置。只用合成地点/测试安排做开发验证。
到实施阶段再核验官方服务协议、接口能力、授权与费用；未获额外许可不购买服务。
时间/天气/车程是估计，标记查询来源与时间，无法查询时清晰报告，不编造结果。
浏览器通知权限由用户本机授予；不得绕过权限、把页面内提示伪称关闭网页后也能送达。

## 用户指定的 Muse 参考布局

以第一张布局图为准：小型顶部伙伴、连续对话、左右气泡、简洁输入、底部三个入口。
原建议四 Tab 改为聊天/我的回忆/提醒；个人设置放右上，聊天记录放左上。
米白/浅灰绿底、绿色动作、18/20/22px 阅读字号、44px 以上触控区域。
原创伙伴“小忆”，参考亲和感，不复制 Muse 角色或标志；安静等待、倾听、思考、回应使用真实状态驱动。
T02 仅显示等待状态及微弱呼吸；其他状态接口预留，未接入语音/模型前不显示虚假处理动画。
减少动态效果时停用呼吸/状态动画。角色不遮挡正文，不持续闪烁/旋转。
