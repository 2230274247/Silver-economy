# T08 记忆检索与引用基线

MemoryRetriever 先在 MySQL 过滤本人、删除/状态、使用许可、有效期、运行模式及可追溯原始用户消息，再排序。跨会话上下文还必须有全局授权；用户显式搜索自己的记忆库允许在关闭AI使用时读取，但不会因此发送给模型。

初版采用SQL：原文主题词命中、中文长串双字词、常用主题同义词/“上…班”表达、英文整词、日期与饮食查询约束。所有文本绑定为参数，LIKE通配符转义；没有付费语义改写/embedding或向量数据库。它是可测的关键词/结构化基线，不等同通用语义理解，复杂改写和大量相似事实的效果在T10E2固定题集测量。

ContextBuilder 每次最多选5条完整事实，证据JSON至多3500 UTF-8字节。总上下文硬限12000字节，最多最近12条，始终给当前原文预留空间；先放弃较旧历史/超预算事实，不截断完整事实或遗漏最新输入。只给模型短M编号、原文/时间精度/候选与Synthetic状态，不把万条记录拼进Prompt。

Prompt chat-memory/v2 在同一次调用生成回复、候选和实际引用编号；未知信息应承认不知道，候选和历史受伤不能当已核实的当前状态，Synthetic须说明合成性质。M编号必须属于本次已选上下文，后台映射真实ID；不信任模型自行提供任意用户/消息ID。

回复提交前重新锁定用户与所引用事实，检查撤回、删除、失效和证据内容/状态变化。变化则丢弃展示正文，保留原始响应和真实用量，completed_rejected不自动重试，避免输出旧信息或重复计费。

memory_uses 以外键同时保证回复归属、记忆归属及(memory_id, source_message_id)真实来源关系；每回复/编号及每回复/来源唯一。历史读取批量JOIN引用，重放不会新增引用或调用模型。来源删除后不再返回引用卡；已经保存的原始对话属于L0，和L1记忆删除不同。

新增 `GET /api/v1/memories/search?q=...`，最多30条相关结果；H5保留空/加载/错误状态、单独源会话入口，聊天显示真实引用卡并可回看原会话。返回的来源仅限已登录用户，B不能读取A的记录、游标或引用来源。

当前证明了小规模真实跨会话闭环；Recall@5/Top1/P95万级指标、完整纠错删除与历史状态规则尚未在此任务验收，继续T09及T10E1/E2。
