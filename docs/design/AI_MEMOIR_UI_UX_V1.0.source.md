# AI 回忆录 App — 全局 UI/UX 设计与交互规范 V1.0

## 0. 规范定位与执行范围

请基于现有 AI 回忆录 App，建立一套完整、统一、可维护的设计系统。

本规范适用于：

- App 的所有现有页面
- 所有导航、弹窗、卡片、按钮、表单及其他组件
- 桌面端、平板端、移动端
- 浅色与深色主题
- 所有交互、动画和状态反馈
- 后续新增的全部功能

**核心要求：本规范属于整个 App，而不是某一个页面的局部改造。**

不要为了实现新的视觉规范而重建项目、删除现有页面或破坏已有功能。应先检查当前项目结构，再逐步建立和应用统一的设计系统。

## 1. 设计理念与产品定位

### 1.1 整体设计方向

采用：

**Apple 式交互品质 + 温暖治愈的情感设计 + 现代简洁的视觉语言。**

产品应传递以下感受：

- 温暖：能够承载真实生活与个人回忆
- 安静：减少视觉噪声，不强迫用户集中注意
- 自然：交互符合直觉，运动遵循物理逻辑
- 精致：字体、留白、材质和动效经过细致设计
- 可信赖：操作结果可预测，用户拥有控制权
- 有情感：具有个性，但不过度拟人化或娱乐化

### 1.2 Apple 设计八项核心原则

整个 App 必须遵循以下原则：

1. **Purpose — 目的明确**  
   每一个元素和动效都必须服务于明确的用户目标。

2. **Agency — 用户掌控**  
   允许用户自主选择、取消、返回、撤销，不强制流程。

3. **Responsibility — 责任与信任**  
   保护个人隐私，清晰说明 AI 行为和数据用途。

4. **Familiarity — 熟悉感**  
   使用符合用户经验的导航、手势和交互规则。

5. **Flexibility — 灵活适应**  
   适配不同设备、内容长度、操作方式和使用能力。

6. **Simplicity — 简单清晰**  
   降低操作复杂度，而不是仅仅减少界面元素。

7. **Craft — 设计品质**  
   注重对齐、间距、排版、材质、状态和动画细节。

8. **Delight — 愉悦体验**  
   通过自然、可靠、细腻的体验传递愉悦，而不是堆砌特效。

### 1.3 禁止的设计倾向

- 不要直接复制 iOS 系统界面。
- 不要将整个 App 做成手机系统设置页。
- 不要滥用毛玻璃、霓虹光、巨大渐变和悬浮卡片。
- 不要为了追求极简而隐藏必要功能。
- 不要出现过度密集的后台管理式布局。
- 不要让所有组件都持续播放动画。
- 不要采用缺乏统一规则的随机圆角、阴影和间距。

## 3. 全局视觉设计系统

### 3.1 设计 Token

所有组件必须使用统一的设计变量，不允许在各个页面中随意写死颜色、间距、阴影和动画参数。

建立以下 Token：

**颜色**

- `color-background`
- `color-surface`
- `color-surface-elevated`
- `color-text-primary`
- `color-text-secondary`
- `color-text-tertiary`
- `color-accent`
- `color-accent-hover`
- `color-border`
- `color-separator`
- `color-success`
- `color-warning`
- `color-error`
- `color-focus`
- `color-overlay`

**空间**

- `spacing-xs`
- `spacing-sm`
- `spacing-md`
- `spacing-lg`
- `spacing-xl`
- `spacing-2xl`

**形状与层次**

- `radius-sm`
- `radius-md`
- `radius-lg`
- `radius-xl`
- `shadow-sm`
- `shadow-md`
- `shadow-lg`
- `elevation-base`
- `elevation-floating`
- `elevation-modal`

**动画**

- `motion-fast`
- `motion-normal`
- `motion-slow`
- `spring-default`
- `spring-gesture`

这些变量应通过现有项目的主题方案统一管理。

### 3.2 布局规范

建议采用 4px 为基础单位的间距系统：

| 用途 | 参考值 |
|---|---|
| 极小间距 | 4px |
| 紧凑间距 | 8px |
| 常规元素间距 | 12–16px |
| 卡片内部留白 | 16–24px |
| 内容分组间距 | 24–32px |
| 大区块间距 | 40–64px |

这些数值是设计基准，可以根据设备尺寸与内容密度进行调整。

要求：

- 使用统一的栅格和对齐规则。
- 相同类型组件保持相同间距。
- 相关内容靠近，不相关内容适当分离。
- 避免无意义的嵌套容器。
- 桌面端设置合理最大内容宽度，避免大屏阅读距离过长。
- 移动端保留舒适的左右边距。

### 3.3 圆角

建议建立四级圆角：

- 小型按钮、标签：8–12px
- 普通输入框、控件：12–16px
- 普通内容卡片：16–20px
- 重要照片卡片、弹层：20–28px

同一层级使用统一圆角，不允许随机设定。

避免所有组件都使用最大圆角。

### 3.4 阴影与空间层级

使用少量、统一的柔和阴影。

- 普通卡片：极浅阴影或细边框
- 悬浮卡片：适度增强阴影
- 弹窗与浮层：明显但克制的空间分离
- 按下状态：阴影可减弱，模拟接近表面

不要使用厚重的纯黑阴影。

不要同时叠加多层明显阴影。

### 3.5 毛玻璃与半透明材质

允许在导航栏、底部操作栏、浮动工具栏和弹层中使用半透明材质。

规则：

- 只在有实际层级关系时使用。
- 不能影响文字可读性。
- 不应在多层容器上反复叠加模糊。
- 背景复杂时应增强表面不透明度。
- 深色主题下需要独立调整材质和阴影。
- 用户开启降低透明度偏好时，应使用较实的背景替代模糊。

## 4. 全局主题系统

### 4.1 默认主题

默认使用「晨间放松」。

五种原始颜色：

`#F3D6D2 #B8DCC8 #C7E4EE #F6E7B5 #F8FBF5`

设计方向：

柔和、温暖、干净、亲切。

以舒适的浅色背景为主，粉色、绿色、蓝色和浅黄色作为辅助色与强调色。

不要让全部色彩同时争夺注意力。

前四种为浅色主题，后五种为深色主题。

每套主题都需要独立生成合适的语义颜色 Token。

不要简单将五种颜色按固定顺序映射到背景、按钮、文字等元素。

### 4.3 主题切换

- 在现有主题设置入口中提供全部九种主题。
- 每套主题展示名称与五色预览。
- 当前主题具有清晰选中状态。
- 切换后全局组件同步更新。
- 用户选择必须持久化。
- 首次使用时默认「晨间放松」。
- 不允许出现切换后的短暂白屏或错误颜色闪烁。
- 主题切换不应重置页面数据、输入内容或阅读位置。

主题变化可以使用约 180–250ms 的柔和过渡。

避免对整个页面进行大面积明暗闪烁。

如果用户要求减少动态效果，则应缩短或移除主题过渡。

### 4.4 对比度

目标遵循 WCAG AA：

- 普通文字对比度不低于 4.5:1
- 大号文字对比度不低于 3:1
- 重要控件边界与图形信息保证可辨识

不要直接使用浅粉、浅蓝或浅绿作为白底正文文字。

深色主题也不能简单采用纯黑背景加刺眼纯白文字。

## 5. 全局排版规范

### 5.1 字体

优先使用当前平台具有良好中文支持的系统字体。

建议字体栈：

`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Noto Sans SC", system-ui, sans-serif`

根据实际平台和字体可用性降级。

不要强制所有设备下载不必要的字体文件。

### 5.2 字体层级

建议以以下层级为起点：

| 层级 | 参考字号 |
|---|---|
| 页面主标题 | 28–34px |
| 区块标题 | 22–26px |
| 卡片标题 | 17–20px |
| 正文 | 16–17px |
| 次要信息 | 14–15px |
| 辅助标签 | 12–14px |

字号应随屏幕尺寸和用户字体设置进行适配，而不是全局固定不变。

### 5.3 文字细节

- 中文正文保持舒适行高，建议 1.5–1.7。
- 大标题可使用相对紧凑的字间距和行高。
- 正文优先正常字距。
- 不要通过过度使用不同字号来制造层级。
- 优先组合字号、字重、颜色和留白建立信息层次。
- 避免文字被图片、高光或透明材质干扰。
- 支持较大字体设置和 200% 文字缩放，不得出现严重截断与重叠。

## 6. 全局交互动效规范

### 6.1 即时反馈

所有可交互元素都必须在用户开始操作时提供反馈。

包括：

- 按钮
- 卡片
- 开关
- 标签
- 导航项
- 图片
- 输入框
- 菜单

按下时可以使用轻微颜色变化、缩放或材质变化。

不能让用户等待业务请求完成后，界面才显示按下状态。

### 6.2 直接操控

用户拖动内容时，应具有接近 1:1 的跟手感。

- 使用 Pointer Events 统一处理输入。
- 必要时使用 `setPointerCapture`。
- 保留用户开始拖动时的相对位置。
- 采用合理的手势识别阈值，避免轻微触碰被误判为滑动。
- 区分水平滑动、垂直滚动和点击。
- 不允许卡片触摸事件无故阻断页面正常滚动。

### 6.3 可中断动画

用户应当能够在动画运行中重新操作。

例如：

- 卡片正在复位时，可以再次拖动。
- 抽屉正在关闭时，可以反向展开。
- 页面滑动过程中，可以立即改变方向。

新的动画必须从当前实际显示位置开始。

不允许突然跳回旧动画的起点。

### 6.4 Spring Animation

对于可被直接操控的对象，优先采用弹簧动画。

参考初始参数：

| 类型 | 阻尼比参考 | 响应时间 |
|---|---|---|
| 普通移动 | 1.0 | 0.3–0.4s |
| 卡片复位 | 1.0 | 0.3–0.4s |
| 手势甩动后回弹 | 约 0.8 | 0.3–0.4s |
| 抽屉和浮层 | 约 0.8–1.0 | 0.3–0.4s |

以上是设计参考，不是要求所有组件使用完全相同的参数。

只在确实由动量产生的交互中使用适度弹跳。

### 6.5 速度与惯性

需要惯性的交互包括：

- 可以甩动的卡片
- 可拖动的轮播
- 底部抽屉
- 可移动的浮动面板

在这些交互中：

- 记录最近的指针位置和时间。
- 计算释放速度。
- 根据速度预测合理的停靠位置。
- 将当前速度传递给后续弹簧动画。
- 在边界处采用适度阻尼，避免突然硬停。

普通按钮和页面切换不需要额外添加惯性。

### 6.6 空间一致性

同一个对象出现和消失时，运动路径应保持一致。

例如：

- 从右侧进入的侧栏，应向右退出。
- 从卡片打开的详情，应在视觉上与原卡片保持联系。
- 从按钮展开的菜单，应围绕触发位置展开。
- 关闭详情后，用户应能回到原先的内容位置。

### 6.7 动画克制原则

禁止：

- 所有卡片持续悬浮
- 长时间自动旋转
- 大面积动态背景
- 不必要的随机弹跳
- 过度夸张的页面缩放
- 多种动画同时争夺注意力

动画的作用应是解释变化、回应操作与建立情绪。

## 7. 全局组件规范

建立统一的组件库或组件规范，优先复用现有成熟组件。

### 7.1 按钮

至少包括：

- Primary
- Secondary
- Tertiary
- Destructive
- Icon Button

每类按钮都必须支持：

- 默认状态
- 悬停状态
- 按下状态
- 键盘焦点
- 禁用状态
- 加载状态

移动端主要操作目标建议不小于 44×44 CSS px 的有效点击区域。

按钮视觉大小可以较小，但可点击区域必须充足。

### 7.2 卡片

统一：

- 圆角
- 内边距
- 边框
- 阴影
- 图片裁切
- 标题层级
- 点击反馈
- 选中状态

不是所有卡片都需要悬浮动画。

只有具有明确交互价值的卡片才使用增强动效。

### 7.3 输入框

输入框应支持：

- 默认
- Focus
- Filled
- Disabled
- Error
- Success

要求：

- 标签明确
- 占位符不能替代必要标签
- 错误提示说明问题与解决方法
- 避免用户输入后才发现整个表单存在大量错误
- 移动端打开键盘后，输入框不能被遮挡
- 不允许因字体过小导致移动端浏览器自动异常缩放

### 7.4 弹窗与底部抽屉

- 根据设备选择适合的表现形式。
- 桌面端优先使用合理尺寸的对话框或浮层。
- 移动端可以使用底部抽屉。
- 弹窗打开后焦点进入弹窗。
- 关闭时焦点恢复到原触发元素。
- 提供明确的关闭方式。
- 非阻断操作不应滥用模态弹窗。
- 不要为了普通提示连续弹出多个确认窗口。

### 7.5 导航

- 主导航位置和名称保持一致。
- 当前页面状态清晰。
- 支持返回和退出。
- 避免过深的导航层级。
- 不因主题变化而改变导航位置。
- 桌面端和移动端可以调整布局，但核心功能路径应保持一致。

## 8. 全局状态反馈规范

所有涉及数据加载或异步请求的页面，必须设计完整状态。

### Loading

- 可预期的短操作使用轻量加载反馈。
- 内容区域加载可以采用骨架屏。
- 避免整页无意义空白。

### Empty

- 说明当前没有内容。
- 根据实际功能提供合理的下一步。
- 空状态可以具有温暖的视觉表达，但不能遮挡主要操作。

### Error

- 清晰解释发生了什么。
- 提供重试或返回方式。
- 保留用户已输入的内容。
- 不向普通用户直接展示复杂技术错误。

### Success

- 对重要操作提供明确结果。
- 避免所有成功操作都使用强烈动画或弹窗。

### Undo

- 对可恢复操作优先提供撤销。
- 对不可恢复的删除操作提供适当保护。
- 不得让用户误以为尚可恢复实际上已经永久删除的数据。

## 9. 回忆模块专属规范

### 9.1 页面定位

「回忆」是整个 App 中最具有情感价值的内容空间。

不应被设计成普通文件管理器、图片上传列表或后台数据库。

参考情绪：

- 私人记忆画册
- 生活故事
- 家庭相册
- 轻量时间轴
- 温暖的图文记录

采用独立、有设计感的页面构成。

此前提供的图 2 仅用于解释功能结构，不得直接复刻。

### 9.2 倾斜追光

参考：

https://jdb156158.github.io/vibe-cards1/

实现要求：

- 使用 3D perspective。
- 使用 rotateX、rotateY 映射指针位置。
- 通过渐变叠层形成柔和高光。
- 高光方向随指针变化。
- 最大倾斜角度建议 5°～8°。
- 指针离开后使用弹簧动画复位。
- 复位过程支持重新交互。
- 移动端采用按住拖动的方式触发。
- 不影响正常滚动、点击和图片浏览。
- 用户启用减少动态效果时自动减弱或关闭。

追光是展示照片的细节增强，不是整个页面的持续动画背景。

### 9.3 图片布局

- 根据真实内容采用合适的图片比例。
- 优先保留照片主体。
- 不强制将所有回忆图片裁切成相同比例。
- 允许精选回忆采用更大的展示尺寸。
- 标题、日期与描述应形成清晰的阅读关系。
- AI 生成图片与真实照片需要可辨识的来源标识。
- 点击后进入详情，支持查看完整内容。

## 10. AI 回忆生图规范

### 10.1 功能原则

AI 生图用于帮助用户艺术化地表达真实回忆。

不能用 AI 自动虚构用户的人生经历。

### 10.2 用户控制

- 用户明确开启后才可使用授权范围内的对话生成回忆。
- 允许用户检查、修改或删除提取的回忆信息。
- 不得擅自生成未经授权的真人肖像。
- 支持关闭自动生成。
- 支持重新生成。
- 支持删除 AI 图片。
- 明确区分真实照片与生成插画。

### 10.3 生成体验

使用异步任务，包含：

1. 识别回忆
2. 提取已知信息
3. 生成图像提示词
4. 生成图片
5. 显示预览
6. 关联回忆
7. 保存或重新生成

需要提供合理的加载、失败、重试和完成状态。

生成图片应兼容整个 App 的视觉风格，但不应因为用户切换主题，就自动修改原始回忆图片的内容。

## 11. 移动端与响应式规范

### 11.1 响应式策略

优先根据内容和功能设置断点，而不是简单按设备名称划分。

重点适配：

- 320–430px 手机
- 768px 左右平板
- 1024px 及以上桌面端
- 更宽屏幕与可调整尺寸的窗口

### 11.2 移动端要求

- 内容不允许出现无意的横向滚动。
- 控件适合手指操作。
- 正确处理屏幕安全区域。
- 底部操作栏不能遮挡主要内容。
- 软键盘弹出时不应破坏布局。
- 长标题和长文字能够正常换行。
- 图片加载不能引起严重页面跳动。
- 不依赖 Hover 才能完成必要操作。
- 优先保持自然滚动体验。

### 11.3 桌面端要求

- 合理使用更大的空间。
- 不将手机布局简单拉宽。
- 支持鼠标与键盘。
- 保持合适的正文阅读宽度。
- 需要时提供更高效的多栏布局。
- 不添加只有装饰作用的大面积空白。

## 12. 无障碍与个性化

整个 App 必须支持：

- 键盘操作
- 明确的 Focus 状态
- 屏幕阅读器可理解的标签
- 合理的语义化结构
- 文字放大
- 高对比度
- 减少动态效果
- 降低透明度
- 不依赖颜色单独传递状态

针对动效偏好：

- `prefers-reduced-motion: reduce`
- `prefers-reduced-transparency: reduce`
- `prefers-contrast: more`

在支持的环境中读取这些偏好并适配。

减少动效并不等于取消所有反馈。可以使用更短、更柔和的颜色或透明度变化代替大幅位移。

## 13. 性能规范

### 13.1 动画

- 以流畅、稳定的高帧率交互为目标。
- 优先使用 `transform` 和 `opacity`。
- 使用 `requestAnimationFrame` 协调逐帧更新。
- 避免持续强制布局计算。
- 不要在每次指针移动时重渲染整个页面。
- 避免无意义的 `transition: all`。
- 不要为大量静止元素永久设置 `will-change`。
- 对复杂动画进行真实设备测试。

### 13.2 图片

- 使用合适的图片尺寸。
- 支持响应式图片资源。
- 长列表中的非首屏图片延迟加载。
- 为图片容器预留合理尺寸，降低布局偏移。
- 采用合适的图片压缩策略。
- 缩略图与原图分开管理。
- 不因视觉效果损害照片的清晰度。

### 13.3 页面

- 避免不必要的 JS 和大型动画依赖。
- 优先复用项目已有能力。
- 对长列表考虑虚拟化。
- 不使用持续运行的装饰动画消耗设备性能。
- 优化首次打开、页面切换和返回操作的体验。

## 14. 图标与视觉资产

- 全部图标采用统一风格。
- 图标线宽和尺寸保持一致。
- 同类操作使用相同图标。
- 避免混用多套不协调的图标库。
- 不依赖图标颜色单独表达含义。
- 图标按钮提供可访问名称。
- 插画、照片和装饰图案应符合产品统一的情感方向。

真实照片优先保持自然色彩。

AI 插画可以具有不同艺术风格，但展示容器、边距、标签和交互必须统一。

## 15. 内容与文字规范

App 的文字风格应当：

- 自然
- 简洁
- 温暖
- 清晰
- 尊重用户
- 避免过度拟人化

不使用生硬的技术术语解释普通操作。

错误提示应告诉用户如何恢复。

AI 生成内容应明确说明生成来源，不得制造不真实的确定感。

不要使用大量感叹号、表情符号和夸张的庆祝文案。

## 17. 开发执行流程

请按照以下顺序进行。

**第一阶段：现状审查**

检查当前项目：

- 页面结构
- 导航方式
- 组件体系
- 现有主题代码
- 动画实现
- CSS 组织方式
- 响应式处理
- 已知体验问题

输出全局 UI 审查清单。

**第二阶段：设计系统**

建立统一的：

- 颜色 Token
- 字体层级
- 间距规范
- 圆角与阴影
- 组件状态
- 动画参数
- 响应式规则

尽量保留已有组件接口，减少对业务逻辑的影响。

**第三阶段：全局应用**

将规范应用到所有现有页面。

禁止只修改首页或回忆页面后就宣称完成全局 UI 升级。

**第四阶段：功能增强**

实现：

- 九套主题切换
- 回忆模块的高质量布局
- 倾斜追光效果
- AI 回忆插画的展示与相关交互

**第五阶段：真实验收**

完成跨设备、跨主题、交互、无障碍和性能测试。

列出仍未解决的问题及原因，不得将未验证的部分宣称为已完成。

## 18. 最终设计标准

这款 App 的设计目标不是模仿 Apple 的外观，而是达到 Apple 式产品在以下方面的品质：

- 自然
- 流畅
- 一致
- 可靠
- 精致
- 易理解
- 可掌控

同时保留 AI 回忆录自身的温暖与情感表达。

**最终判断标准：用户不需要思考界面如何操作，便能自然地使用它；界面不会过度打扰用户，却能在重要时刻提供恰到好处的回应。**

请将本规范视为整个 App 长期遵循的全局设计约束，而不是一次性的 UI 修改任务。
